Requisitos de segurança desde a elicitação

A segurança deixa de ser uma frase genérica quando é descoberta nas entrevistas e escrita como comportamento esperado do sistema.

Ideias essenciais

01Funcional não basta⌄

Uma funcionalidade descreve o que o sistema faz. Um requisito não funcional define qual qualidade esse comportamento precisa manter, como segurança e disponibilidade.

02Entrevista orientada a risco⌄

Além de perguntar o fluxo normal, pergunte o que não pode acontecer, quais dados são sensíveis e quem pode executar cada ação.

Use na prática: Use perguntas abertas antes de propor controles.

03Requisito verificável⌄

'O sistema deve ser seguro' não orienta implementação. Prefira regras como 'somente usuários autorizados podem consultar determinado dado'.

Use na prática: Todo requisito deve permitir uma verificação posterior.
